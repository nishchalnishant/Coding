# 23. 4 Sum

> [!abstract] Problem at a glance
> **Task:** Return all unique quadruplets summing to `target`, each sorted, in lexicographic order.

## 1. Problem

Given an integer array `nums` and an integer `target`, return all unique quadruplets `[a, b, c, d]` of distinct indices whose values sum to `target`. Each quadruplet is sorted, and the list is sorted.

| Input | Output | Why |
|---|---|---|
| `nums = [1, 0, -1, 0, -2, 2], target = 0` | `[[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]` |  |
| `nums = [2, 2, 2, 2, 2], target = 8` | `[[2, 2, 2, 2]]` |  |

**Constraints:** `1 ≤ n ≤ 200`, `−10⁹ ≤ nums[i], target ≤ 10⁹`.

---

## 2. Approaches at a glance

| Approach | Idea | Time | Space |
|---|---|---|---|
| Three loops + hash set | fix i, j; set lookup for the fourth among k's seen | O(n³ log m) | O(n + #quads) |
| Sort + two fixed + two pointers | i, j loops with skips; l/r on the rest | O(n³) | O(1) beyond the output |

---

## 3. Three loops + hash set

**Intuition.** For each `i < j`, scan `k > j` with a set of values seen between `j` and `k`; the fourth is `target − (a + b + c)`. A global set dedupes.

```python
def four_sum_hash(nums, target):
    n, res = len(nums), set()
    for i in range(n):
        for j in range(i + 1, n):
            seen = set()
            for k in range(j + 1, n):
                d = target - (nums[i] + nums[j] + nums[k])
                if d in seen:
                    res.add(tuple(sorted((nums[i], nums[j], nums[k], d))))
                seen.add(nums[k])
    return sorted(list(t) for t in res)
```

**Complexity:** time **O(n³ log m)**, space **O(n + #quads)**.

## 4. Sort + two fixed + two pointers

**Intuition.** Same reasoning as 3Sum: inside a fixed `(i, j)`, the pair sum is monotone in `l` and `r`. Skip `j` when `j > i + 1 and nums[j] == nums[j − 1]`. The `j` condition is relative to `i + 1`, not to 1.

**Pruning:** if `nums[i] + nums[i+1] + nums[i+2] + nums[i+3] > target`, break; if `nums[i] + the three largest < target`, continue. These don't change the worst case but help a lot in practice.

**C++**
```cpp
vector<vector<int>> fourSum(vector<int>& nums, int target) {
    sort(nums.begin(), nums.end());
    vector<vector<int>> res;
    int n = nums.size();
    for (int i = 0; i < n; i++) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        for (int j = i + 1; j < n; j++) {
            if (j > i + 1 && nums[j] == nums[j - 1]) continue;
            int l = j + 1, r = n - 1;
            while (l < r) {
                long long s = (long long)nums[i] + nums[j] + nums[l] + nums[r];
                if (s < target) l++;
                else if (s > target) r--;
                else {
                    res.push_back({nums[i], nums[j], nums[l], nums[r]});
                    l++; r--;
                    while (l < r && nums[l] == nums[l - 1]) l++;
                    while (l < r && nums[r] == nums[r + 1]) r--;
                }
            }
        }
    }
    return res;
}
```

static List<List<Integer>> fourSum(int[] nums, int target) {
    Arrays.sort(nums);
    List<List<Integer>> res = new ArrayList<>();

**Python**
```python
def four_sum(nums, target):
    nums.sort()
    n, res = len(nums), []
    for i in range(n):
        if i > 0 and nums[i] == nums[i - 1]:
            continue
        for j in range(i + 1, n):
            if j > i + 1 and nums[j] == nums[j - 1]:
                continue
            l, r = j + 1, n - 1
            while l < r:
                s = nums[i] + nums[j] + nums[l] + nums[r]
                if s < target:
                    l += 1
                elif s > target:
                    r -= 1
                else:
                    res.append([nums[i], nums[j], nums[l], nums[r]])
                    l += 1; r -= 1
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1
                    while l < r and nums[r] == nums[r + 1]:
                        r -= 1
    return res
```

**Complexity:** time **O(n³)**, space **O(1) beyond the output**.

## Edge cases

- n < 4 → [].
- Overflow: four values of 10⁹ (the 32-bit sum wraps to the target in one LC test).
- All equal values.

---

## Common mistakes

1. 32-bit sum → false matches after overflow.
2. `j` duplicate check against `j > 1` instead of `j > i + 1`.
3. Forgetting to move both pointers on a hit.
